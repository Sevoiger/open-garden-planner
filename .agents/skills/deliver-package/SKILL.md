# Deliver related changes

Derive observable acceptance from the requested package. Inspect the common code
paths and implement coherent slices, preserving unrelated work. Split branches
only when it makes independent delivery clearer. Use existing commands and services.

Choose shared integration evidence where several changes cross the same boundary;
do not multiply checks per issue or add mandatory documentation per slice. Resolve
failures introduced by the package, then apply AGENTS.md review and draft-PR policy.
Report implemented outcomes, actual evidence and remaining limits per relevant area.
No frozen build, release or upstream work belongs to this personal fork workflow.
