# Audit fonctionnel MCP — 26 octobre 2026

Le cycle horticole synthétique est démontré sur le transport HTTP MCP et les
providers Qt de production. **L’application n’est pas certifiée entièrement
pilotable** : plusieurs commandes existantes ne disposent pas encore d’une preuve
individuelle de bout en bout. La présence d’une action dans l’inventaire, d’un
outil, d’un test de service ou d’un rendu ne change pas ce statut.

## Provenance et protection du projet réel

- Point de départ : commit `4e78aa8`, après `e0c160c` (pilotage Qt), application
  source `1.30.10`, Python 3.11.17, Qt/PyQt 6.11.0, SDK MCP 1.30.0.
- Processus réellement observé : `.venv/bin/python -m open_garden_planner`, PID
  3834, démarré à 09:01:50 le 26 octobre. `lsof` identifie l’écoute loopback
  **8766** ; `.codex/config.toml` désigne encore 8765. Aucune configuration du
  compte Codex n’a été modifiée.
- Lecture MCP authentifiée du serveur actif : `writes_enabled=true`, 76 outils,
  2 361 nœuds Qt avec `include_hidden=true,max_nodes=10000`, sans troncature.
  `MonJardin.ogp` est propre, 0 plante, 0 massif, 6 autres objets. Ces lectures
  reproduisent les constats fournis ; ce jardin n’a servi à aucune écriture d’essai.
- L’ancien `initialize` annonçait `1.30.0`, version du SDK, sans version OGP dans
  `get_capabilities`. La correspondance binaire exacte avec un commit ne pouvait
  donc pas être certifiée rétrospectivement. Les descriptions des outils et le
  lancement depuis ce dépôt concordaient avec l’implémentation initiale.
- Les fixtures redirigent QSettings et les stockages fichiers avant construction
  des fenêtres ; les projets, lots et pièces jointes sont synthétiques, dans des
  répertoires temporaires. Les essais HTTP utilisent des ports éphémères et un
  jeton de test. Aucun nettoyage par undo n’a été effectué sur le jardin réel.
- Les modifications personnelles préexistantes de `examples/jardin-demo.ogp`,
  `projects/`, `3d print/` et `docs/analyse_sol_brute.md` sont exclues du diff.

## Inventaire et lecture de la matrice

L’inventaire part des modèles, actions de menus, onglets, panneaux et dialogues,
ainsi que des menus contextuels des items du canevas. Les familles de sources
principales sont `app/application.py`, `ui/canvas/items/garden_item.py`,
`ui/canvas/canvas_view.py`, `ui/views/`, `ui/dialogs/`, `ui/panels/` et `models/`.
Le script suivant produit un inventaire JSON reproductible avec fichiers et lignes,
indépendant des seuls outils MCP :

```bash
.venv/bin/python scripts/audit_mcp_inventory.py --output /tmp/ogp-mcp-source-inventory.json
```

Au premier relevé : 763 déclarations, dont 95 QAction, 88 ajouts d’actions,
23 menus, 11 ajouts d’onglets, 40 classes de dialogues et 47 classes de modèles.
Les déclarations comprennent variantes et composants ; ce n’est pas un nombre de
fonctions indépendantes. Le JSON les marque conservatoirement `non_testee` : c’est
un index des sources, pas un calcul automatique de couverture. Les catalogues
générés et menus conditionnels exigent en complément l’inventaire Qt au moment
du parcours. Les menus contextuels de récoltes et le Gantt ont été réellement
actionnés dans les scénarios ci-dessous.

Dans les tableaux : **E** = validée de bout en bout pour le scénario indiqué,
**P** = partielle, **N** = non testée individuellement via MCP, **D** = défaillante,
**—** = non applicable. Les colonnes L/C/M/S sont lecture/création/modification/
suppression. `✓` signifie démontré via MCP ; `Qt` indique une possibilité repérée
dans le produit sans preuve complète. U = undo/redo ; `sans` signifie absence
d’undo dans le produit, pas oubli de test. Pst = sauvegarde/réouverture, ou sortie
relue lorsqu’il s’agit d’un export. Une cellule `?` reste non vérifiée.

Les échecs de sauvegarde testés (projet neuf sans chemin, répertoire parent absent)
renvoyaient déjà des erreurs explicites : **pas de défaut confirmé dans ces cas**.
Le timeout PNG est confirmé pour les lectures du projet réel. La sauvegarde utilise
le même encodeur corrigé et passe sur données synthétiques ; aucune sauvegarde
d’essai n’a été demandée sur le fichier personnel.
L’hypothèse ancienne « toute contrainte interdit le déplacement » est réfutée par C ;
le correctif récent du dépôt est conservé et ses régressions réexécutées.

## Procédure de vérification MCP

1. Démarrer une instance avec stockages et réglages isolés ; identifier son port
   réel et utiliser son jeton. Lire `get_capabilities`, `initialize` et comparer
   l’empreinte/version avant d’interpréter la liste d’outils. Ne jamais commencer
   un essai destructif dans le projet personnel.
2. `new_plan` → `create_object(GARDEN_BED)` → deux `PERENNIAL` ; lire les UUID,
   `get_garden_record`, la contenance et le lien explicite de fiche.
3. Donner successivement mois, inconnu et jour exact avec `set_planting_date` ;
   relire la précision. Enregistrer deux événements semis, `planned` et `done`,
   avec des clés différentes. Rejouer la même clé/charge : même event_id ; changer
   la charge avec cette clé : erreur.
4. Ajouter/corriger observation et arrosage multicibles, vérifier `quantity=null`
   puis zéro, undo/redo, dates et noms historiques. Rechercher les événements.
5. Redécouvrir CanvasView et menus contextuels ; `interact_ui(context_menu)` en
   coordonnées scène ; action Log Harvest. Remplir Entry, valider OK, attendre
   tous les reçus finaux. Relire `garden://plan/raw` et la note de journal liée.
   Ouvrir History, corriger puis supprimer ; gérer la confirmation réelle et undo.
6. Onglets Tasks et Seed Inventory : créer/corriger une tâche, utiliser Done ;
   ajouter/corriger/épuiser/supprimer un lot. Lire en-têtes et identifiants après
   chaque tri/filtre. Le stock est global ; sa persistance se vérifie en rechargeant
   son store isolé, pas par la seule sauvegarde `.ogp`.
7. Localisation synthétique et gel saisis via Qt, calendrier/propagation : lire
   `custom_state`, cliquer une ligne, modifier l’éditeur nommé, attendre le commit
   métier différé ; relire overrides et tâches. Une fenêtre prévue n’est pas un
   événement réalisé.
8. `save_plan(file_path=temp)` → `new_plan` → `open_plan(temp)` ; vérifier
   observations, quantités/unités, dates, liens, récoltes, tâches et rejeu durable.
   L’undo est réinitialisé à l’ouverture. Créer deux saisons par leurs dialogues
   réels et revenir à la précédente par la liste de liens.

Les scénarios exécutables H sont la procédure précise, avec les arguments et
assertions reproductibles. Les helpers n’invoquent aucun widget directement :
ils appellent exclusivement MCP ; les lectures finales indépendantes portent sur
les fichiers de test. Les suites de service S complètent les échecs atomiques.

## Limites distinctes des défauts MCP corrigés

- **Fonctions présentes mais non certifiées** : toutes les lignes N/P ci-dessus.
  Un prochain scénario peut découvrir un défaut applicatif ou de pilotage ; ce
  serait une observation nouvelle, pas une fonction déjà validée par cet audit.
- **Fonctions absentes du produit** : pas de modèle natif de quantité inconnue
  pour un stock ou une récolte ; la récolte spécialisée impose un jour. Pas de
  journal autonome d’état réalisé de chaque étape de pépinière : le calendrier
  décrit des prévisions/overrides, les interventions enregistrent les faits. Aucun
  nouveau module horticole ni précision fictive n’a été ajouté.
- **Undo absent par conception** : stocks globaux, statuts de tâches, préférences
  et overrides de propagation n’ont pas tous une commande annulable. Le MCP
  utilise les chemins du produit et ne prétend pas leur ajouter cet undo.
- **Rejeu** : interventions avec clé persistante ; entrées Qt avec reçus de session.
  `create_object`, `add_manual_task` et les déplacements relatifs métier n’ont pas
  de clé de rejeu durable. Relire leur état après une réponse perdue ; ne pas
  réémettre aveuglément. C’est une limite réelle à la robustesse universelle.
- **Erreurs et reçus** : les handles expirent avec leur QObject/session ; un reçu
  UI `completed` atteste la livraison, pas chaque conséquence différée. La session
  conserve au plus 10 000 clés UI et demande un redémarrage au-delà. Un appel Qt
  déjà commencé ne peut pas être annulé sans risque de demi-mutation.
- **Fichiers** : `save_plan`/exports conservent le contrat historique de confiance
  loopback sans jeton ; les mutations de scène et tout pilotage Qt sont protégés.
  Les écritures de fichiers sont atomiques individuellement, une copie de saison
  et son lien inverse ne constituent pas une transaction multi-fichier ; un échec
  partiel signale précisément le fichier cible déjà créé.
- **Dépendances extérieures** : réseau satellite, lookup météo/gel, fournisseurs
  botaniques et installation de mises à jour non exercés ; aucune permission
  extérieure n’a été étendue pour les tester. Un rendu offscreen n’est pas une
  acceptation visuelle Cocoa de l’ensemble de l’application.
